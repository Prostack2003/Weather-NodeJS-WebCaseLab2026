# Погодный дайджест

Консольная утилита на Node.js для получения прогноза погоды через открытый REST API [Open-Meteo](https://open-meteo.com/).

Программа принимает один или несколько городов, получает их координаты, запрашивает прогноз погоды, выводит результат в терминал и сохраняет отчёты в формате JSON.

## Возможности

- получение прогноза для одного или нескольких городов;
- параллельная обработка городов;
- прогноз на период от 1 до 7 дней;
- вывод результатов в виде таблицы;
- сохранение отчётов в JSON;
- использование кеша за текущую дату;
- принудительное обновление через `--no-cache`;
- обработка сетевых ошибок, тайм-аутов и некорректных ответов API;
- изоляция ошибок: проблема одного города не останавливает остальные.

## Требования

- Node.js 20 или новее;
- npm;
- доступ к интернету для получения свежего прогноза.

Ключ доступа к Open-Meteo не требуется.

## Установка

Клонируйте репозиторий:

```bash
git clone https://github.com/Prostack2003/Weather-NodeJS-WebCaseLab2026.git
```

Перейдите в каталог проекта:

```bash
cd Weather-NodeJS-WebCaseLab2026
```

Установите зависимости:

```bash
npm install
```

Создайте локальный файл с переменными окружения:

```bash
cp .env.example .env
```

Файл `.env` не попадает в репозиторий.

## Переменные окружения

| Переменная           | Назначение                                          | Значение по умолчанию                  |
| -------------------- | --------------------------------------------------- | -------------------------------------- |
| `GEOCODING_BASE_URL` | Базовый URL сервиса геокодирования                  | `https://geocoding-api.open-meteo.com` |
| `FORECAST_BASE_URL`  | Базовый URL сервиса прогноза                        | `https://api.open-meteo.com`           |
| `REQUEST_TIMEOUT_MS` | Максимальное время ожидания запроса в миллисекундах | `5000`                                 |
| `REPORTS_DIR`        | Каталог для сохранения отчётов                      | `reports`                              |
| `TEMPERATURE_UNIT`   | Единица измерения температуры                       | `celsius`                              |
| `PRECIPITATION_UNIT` | Единица измерения осадков                           | `mm`                                   |

Пример файла `.env`:

```dotenv
GEOCODING_BASE_URL=https://geocoding-api.open-meteo.com
FORECAST_BASE_URL=https://api.open-meteo.com
REQUEST_TIMEOUT_MS=5000
REPORTS_DIR=reports
TEMPERATURE_UNIT=celsius
PRECIPITATION_UNIT=mm
```

## Запуск

Основной формат команды:

```bash
node src/index.js --city "Название города" --days 3
```

### Параметры

| Параметр     | Обязательный | Описание                                                |
| ------------ | ------------ | ------------------------------------------------------- |
| `--city`     | Да           | Один город или несколько городов через запятую          |
| `--days`     | Нет          | Количество дней от 1 до 7, по умолчанию `3`             |
| `--no-cache` | Нет          | Игнорировать сохранённый отчёт и выполнить новый запрос |

### Один город

```bash
node src/index.js --city Москва
```

Будет использован прогноз на 3 дня.

### Несколько городов

```bash
node src/index.js --city "Москва, Казань, Владимир" --days 5
```

Лишние пробелы и пустые значения удаляются.

### Запуск без использования кеша

```bash
node src/index.js --city Казань --days 2 --no-cache
```

### Запуск через npm

```bash
npm run run -- --city Москва --days 3
```

## Кеширование и отчёты

Отчёты сохраняются по следующему шаблону:

```text
reports/{город}-{YYYY-MM-DD}.json
```

Например:

```text
reports/Казань-2026-09-11.json
```

Перед обращением к API программа проверяет наличие сегодняшнего отчёта.

Кеш используется, если:

- файл существует;
- в нём присутствуют данные города и прогноза;
- сохранённое количество дней совпадает с запрошенным.

Если файл отсутствует или количество дней отличается, программа получает свежий прогноз и перезаписывает отчёт.

Флаг `--no-cache` принудительно отключает чтение кеша.

Пример структуры отчёта:

```json
{
    "date": "2026-09-11",
    "requestedDays": 2,
    "location": {
        "name": "Казань",
        "country": "Россия",
        "latitude": 55.78874,
        "longitude": 49.12214
    },
    "forecast": {
        "daily": {
            "time": ["2026-09-11", "2026-09-12"],
            "temperature_2m_max": [17.9, 16.6],
            "temperature_2m_min": [7.5, 11.1],
            "precipitation_sum": [0, 8.8]
        },
        "dailyUnits": {
            "time": "iso8601",
            "temperature_2m_max": "°C",
            "temperature_2m_min": "°C",
            "precipitation_sum": "mm"
        }
    }
}
```

Каталог `reports` добавлен в `.gitignore`.

## Обработка ошибок

Программа обрабатывает следующие ситуации:

- параметр `--city` отсутствует;
- после `--city` не указано значение;
- передан неизвестный параметр;
- после `--days` не указано значение;
- количество дней не является целым числом;
- количество дней выходит за диапазон от 1 до 7;
- город не найден;
- API вернул статус `4xx`;
- API вернул статус `5xx`;
- отсутствует подключение к сети;
- превышено время ожидания запроса;
- API вернул некорректный JSON;
- API вернул данные неизвестного формата;
- отчёт невозможно прочитать или сохранить.

Если один город завершился ошибкой, остальные города продолжают обрабатываться.

## Коды завершения

| Код | Значение                                           |
| --- | -------------------------------------------------- |
| `0` | Все города обработаны успешно                      |
| `1` | Ошибка аргументов или ошибка хотя бы одного города |

Проверить код завершения в Linux можно командой:

```bash
echo $?
```

## Архитектура

Работа программы состоит из следующих этапов:

1. `index.js` разбирает и проверяет аргументы командной строки.
2. `weather.service.js` организует обработку городов и работу кеша.
3. `weather.api.js` выполняет запросы геокодирования и прогноза.
4. `report.storage.js` читает и сохраняет JSON-отчёты.
5. `weather.format.js` формирует таблицу и выводит результат в терминал.

Несколько городов обрабатываются параллельно через `Promise.allSettled`. Ошибка одного запроса не прерывает обработку остальных.
